# OpenAsstAI 第一阶段目标

## Goal

在 6 周内交付一个可内测的官方节点 AI Agent 租用 MVP。用户可以从市场选择 Agent 模板，创建一个运行在官方 Linux 节点上的 Agent 实例，并在控制台配置 Models、Channels、Skills，通过 Web Terminal 管理实例。

第一阶段的产品重心是验证：

1. 用户是否愿意租用一个长期在线的 Agent 工作空间。
2. 用户是否能理解并完成 Agent 的模型、通道、技能配置。
3. 平台是否能稳定创建、运行、停止和销毁隔离实例。
4. Web Terminal 是否足够支撑早期用户的远程管理需求。

## Success Metrics

- 新用户从进入市场到创建运行中 Agent 的时间小于 5 分钟。
- 一个官方节点可以稳定承载至少 10 个并发 Agent 实例。
- Agent 实例支持创建、启动、停止、重启、销毁、日志查看。
- 控制台支持配置至少 1 个模型、1 个聊天通道、2 个技能。
- Web Terminal 可以连接到实例沙箱，并执行常见 Linux 命令。
- 平台记录实例生命周期、用户操作、资源用量和费用估算。

## 用户角色

### 租用方 User

想要快速拥有一个长期在线的 Agent，不想自己部署服务器、配置模型、接入聊天通道或维护运行环境。

### 平台管理员 Admin

负责上架官方 Agent 模板、维护官方节点、查看实例健康状态、处理用户问题。

### Provider

第一阶段不开放第三方 Provider 接入，只预留架构接口。第三方 Provider 节点接入放到第二阶段。

## 第一阶段范围

### 1. 市场浏览

- Agent 模板列表。
- Agent 模板详情。
- 价格、运行框架、模型能力、通道能力、技能能力展示。
- 官方模板标识。

### 2. 实例创建

- 用户选择 Agent 模板。
- 用户选择套餐规格：CPU、内存、磁盘、地区。
- 用户创建 Agent 实例。
- 平台分配官方 Linux 节点并创建隔离运行环境。

### 3. Agent 控制台

控制台至少包含：

- Overview：状态、IP/实例 ID、套餐、运行时间、费用估算。
- Models：配置一个模型供应商或用户自带 API Key。
- Channels：第一阶段必须支持 Web Chat，微信/QQ/飞书先做适配器占位和配置模型。
- Skills：安装、卸载、启用、禁用平台内置技能。
- Terminal：浏览器内终端。
- Logs：Agent 日志、系统日志、部署日志。
- Settings：实例名称、重启、停止、销毁。

### 4. Runtime

- 官方 Linux 节点。
- 每个 Agent 实例运行在隔离沙箱中。
- 第一阶段优先使用 Docker 容器，后续再升级为 microVM 或 VM。
- Agent 框架优先支持 Hermes 模板和 OpenClaw 模板。
- 如果第三方框架接入成本高，先用统一 Agent Template Adapter 抽象模板启动、配置和健康检查。

### 5. Web Terminal

- 用户从实例控制台打开终端。
- 终端连接到该实例的隔离环境。
- 支持基本命令执行、窗口 resize、断线重连。
- 终端操作需要写入审计日志。

### 6. 用量和费用

- 第一阶段可以先做费用估算和内部账单，不强依赖真实支付。
- 记录实例运行时长、套餐价格、模型调用量、预估费用。
- 后续再接微信支付、支付宝、Stripe 或企业月结。

## 不做什么

- 不开放第三方 Provider 接入。
- 不支持用户直接租用 Provider 的真实个人电脑。
- 不支持 Windows/macOS 完整远程桌面。
- 不支持手机远程出租。
- 不做公开 Skill 市场和开发者分成。
- 不做复杂 KYC、提现、争议仲裁。
- 不承诺生产级 SLA。

## 验收标准

第一阶段完成时，至少可以演示下面的完整链路：

1. 用户注册或登录。
2. 用户进入市场，选择一个官方 Agent 模板。
3. 用户创建一个 Linux Agent 实例。
4. 实例进入 Running 状态。
5. 用户在 Models 中配置模型。
6. 用户在 Channels 中打开 Web Chat。
7. 用户在 Skills 中启用至少一个内置技能。
8. 用户可以和 Agent 对话。
9. 用户可以打开 Web Terminal 并进入实例沙箱。
10. 用户可以查看日志、重启实例、销毁实例。
11. 管理员可以看到节点、实例、资源用量和错误日志。

## 阶段结束后的判断

如果第一阶段用户能顺利完成租用和配置，并且实例稳定运行，就进入第二阶段：第三方 Provider 节点接入。

如果第一阶段用户主要卡在配置复杂度，就优先强化模板、默认配置和引导流程。

如果第一阶段主要问题是运行稳定性，就先补节点调度、沙箱隔离、日志和恢复能力，不急着扩大市场供给。
